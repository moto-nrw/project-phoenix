# Real-time updates (SSE)

Read before changing event producers, event types, SSE connections, or client
refetch behavior. Backend-relative paths below start at `backend/`;
frontend-relative paths start at `frontend/src/`.

## Backend

- **Hub**: `backend/realtime/` (dependency-neutral package, `*slog.Logger` with nil-safe `getLogger()`). Each process root builds Delivery’s `NewPostgresRealtimeHub` (`backend/modules/delivery/compose/realtime_transport.go`) over its existing pool. Every API listens on `moto_realtime_v1` and fans received signals into its local hub; a standalone Worker only publishes. School/group/account/guardian addressing stays in the envelope; legacy unscoped `BroadcastToAll` remains local and is never relayed. No receive path re-publishes. The root closes the listener before the pool; reconnects and lost messages fall back to client polling. Local-only test hubs use `realtime.NewHub`. See [ADR 0145](../adr/0145-realtime-signale-bleiben-verlustbehaftet-und-laufen-ueber-postgresql.md) and the [Worker runbook](../operations/worker-lease-2726.md#realtime-across-processes-5457).
- **Endpoint**: `/api/sse/events` — JWT-authenticated, auto-subscribes the client to the active groups they supervise, 30s heartbeat.
- **Broadcasting**: services fire events after data changes via `realtime.NewEvent(...)` + `BroadcastToGroup` — fire-and-forget, broadcast errors are logged and never block the operation. Per-client buffers are small and lossy (events drop when a client's channel is full), which is why clients refetch instead of trusting delivery. Broadcast points live in `modules/studentpresence/internal/application/presence/` (visits, sessions, attendance).
- **Event types**: authoritative list in `realtime/events.go` (student check-in/out, activity lifecycle, instance lifecycle, dashboard counts, supervision/arrival-schedule/settings changes). Frontend types mirror it in `frontend/src/lib/sse-types.ts` — keep both in sync.
- Events are notification triggers, not payloads — clients refetch via bulk endpoints.
- **School portal** (moto schule, `/api/school/sse/events`): clients are indexed by account and by school, never by group or tenant fan-out. They get `BroadcastToSchoolAccounts` events, plus `class_day_changed`, which `Hub.BroadcastToTenant` derives from every `student_updated` at the same school (#4792). It carries only the source, never a child; open class views refetch. Every successful morning-attendance save also queues a school-scoped `student_updated` through Delivery's existing after-commit queue; the hub derives `class_day_changed` without child data. This includes corrections to present and works independently of notification settings. The notice `school_unreported_absence` (#4791, „Fehlt ohne Meldung“) separately reaches the Schulverwaltung as a `notification` event; `SchoolRealtimeBridge` also dispatches `class-day-refresh` on it.

## Frontend

Read the [SSE hook](../../frontend/src/lib/hooks/use-sse.ts) for current
options and retry defaults, and its [tests](../../frontend/src/lib/hooks/use-sse.test.ts)
for reconnect/error behavior. Events are triggers: refetch rather than using
them as data payloads.

- Hook: `~/lib/hooks/use-sse` (`status`: `idle | connected | reconnecting | failed`); event types in `lib/sse-types.ts` mirror `backend/realtime/events.go` — keep in sync
- Proxy route `app/api/sse/events/route.ts` bypasses the route wrapper (streaming) with `export const runtime = "nodejs"`, injecting the JWT server-side (no browser bearer tokens)
- After an event for the current group, refetch in bulk: `GET /api/active/groups/{id}/visits/display` (O(1), not per-student)
- `useSSE` uses `FetchEventSource` (`lib/fetch-event-source.ts`) rather than native EventSource. Each actual same-origin BFF stream request carries `X-Moto-Session-Account` from the tab's binding, with cookies; no tokens or account binding in URLs. Tenant, parent and school SSE keep their own auth wrappers, so a stale account is refused **before** backend/stream setup with 409 `identity.session_account_mismatch`; tenant host checks still apply.
- The stream's own refusal envelope takes the existing mismatch path (fetch observer / `apiErrorFromResponse`). There is no preflight or diagnostic second stream. Account/school refusals suspend retries and wake reconnects until the provider confirms its session; the confirmation replaces a refused, failed or closed connection, even for the same account. An open or opening stream of the same account stays open across provider answers (session poll, `update()`, #5017) while its admin flag, roles and permissions are unchanged; a new account or changed authorization replaces it. Reordering roles or permissions alone does not replace the stream. While the confirmed tenant session names another school than the page, `useGlobalSSE` opens no stream: every confirmation would repeat the school refusal, and that loop of session lookups can write the old cookie back after „Zur Schulanmeldung“. The stream resumes once the session names the page's school again. Other HTTP/network errors keep the bounded exponential backoff with jitter. Replacement, disabling and unmount abort the request and clear timers/listeners.
- Heartbeat watchdog (#5017): the backend writes a heartbeat comment every 30 s. `FetchEventSource` resets an idle timer on every received byte; after `SSE_IDLE_TIMEOUT_MS` (75 s) of silence it aborts the half-open stream as dropped, so `useSSE` reconnects with its backoff, the live channel falls back to the 60 s poll, and the reconnect reconciles.
- Named/default events, UTF-8 chunks, CR/LF/CRLF, multiline data and heartbeat comments follow SSE framing. `id` and `retry` fields are ignored: this API has no replay buffer, and the hook owns retry timing.
- **Live sync (#5017).** `useGlobalSSE` binds its stream to the SWR scope (school and account, `useLiveEventScope` in `~/lib/swr`). An event acts only while that binding is the session's scope and no other tab's session change is pending; a burst collected for a previous binding is dropped. While the stream is connected it is published as the live channel, and readers that poll only for other people's changes use `useLiveRefreshInterval(fallbackMs)`: five minutes with a connected stream of their own scope, `fallbackMs` (default 60 s) otherwise. SWR skips interval polls in hidden tabs. After a reconnect `useGlobalSSE` reconciles at once every cache its events keep fresh; the first connection of a binding reconciles once after `STARTUP_RECONCILE_DELAY_MS` (3 s) plus up to 2 s jitter, for events between the page load and the open. Both cover the unread and request counters, but neither the companion bus nor the group subscription. Synthetic reconnect invalidations spare the sidebar; sidebar notifications from real queued activity or group-access events are still delivered in the same flush. Hidden tabs reconcile when they become visible; a flapping stream reconciles at most once per `RECONCILE_MIN_GAP_MS` (30 s), with one trailing reconcile. A new poll of SSE-driven data uses the hook instead of a fixed interval and gets an invalidation in `flushInvalidations`.
- Connection drops usually mean an expired JWT (lifetime configured by `AUTH_JWT_EXPIRY`) or no supervised active groups
