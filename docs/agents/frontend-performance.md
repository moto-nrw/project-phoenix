# Frontend performance guardrails

Read before changing bundle baselines, shell rendering, or performance tooling.
Paths below are relative to `frontend/` except `.github/` and `docs/`.

## Ratchets and evidence (#2939)

- **Bundle budgets** (CI job `frontend-build`, blocking): `pnpm run perf:bundle-ratchet` compiles cold with `next experimental-analyze` and checks compressed client JS against independently reviewed `scripts/perf/bundle-budgets/<portal>/<resource>.json`. Each route has approved `referenceBytes` and a fixed `maxBytes`. The migration preserves every previous ceiling exactly: reference plus the larger of 2% or 10 KiB. These are policy, not current measurements. Improvements and removed routes do not fail or force policy edits; new routes still need an explicit reviewed budget. Budget increases require a reason in the PR, never an automatic `--update` or artifact copy. Keeping the absolute ceiling prevents cumulative small increases from escaping a rolling PR-delta check.
- **Bundle observations**: each head build writes `perf-results/bundle-measured.json`, format `moto-bundle-measurement/v1`, with compressed route bytes, producer revision/run and a strict source-tree/build-configuration identity. The artifact name includes its identity key. CI reuses an existing successful same-repository main/nightly run's matching observation for the pinned base, rather than building the base again. The key uses the frontend Git tree, not commit identity, so equal source trees can survive PR synthetic merges becoming real merges. Node/platform, build environment (hashed, never exposed), local env file fingerprints and the analyzer recipe are part of configuration identity. A stale, foreign or corrupt artifact is rejected. A genuine miss is reported as **base comparison not performed**, while absolute approved budgets are still enforced. Base deltas are informative, not policy. Artifacts expire after 14 days; a miss never starts an extra base build. GitHub PR-scoped Actions caches are not used as cross-PR evidence storage.
- **Cold analysis and regular build**: both remain required. Chunk splits depend on Turbopack's incremental cache, so the analysis parks and restores that cache and compiles cold. `--skip-analyze` accepts only an existing analysis with matching source/configuration identity, not arbitrary stale diagnostics. The ordinary `next build` remains because the experimental analyzer has not been proved equivalent for all type/route/build validations. Linux CI measurements must not be silently replaced with macOS observations. Source-addressed observations require committed frontend sources; an uncommitted working tree cannot be labeled as the HEAD tree.

- **Render budget** (Vitest, blocking): `expectIdleRenderBudget` from `src/test/render-budget.tsx` counts `<Profiler>` commits over 5 s of fake-timer idle and caps them at 20; `mobile-bottom-nav.test.tsx` and `sidebar.test.tsx` use it. A new effect loop in the shell trips this regardless of runner speed. Keep the cap; fix the loop. Reuse the helper for any new always-mounted component.
- **Nightly counters** (`.github/workflows/perf-nightly.yml`, non-blocking): runs `pnpm run perf:trace` and `pnpm run perf:render` against a seeded backend on weeknights and via `workflow_dispatch`; the report lands in the job summary and as a 30-day artifact. Compare counters (requests per screen, duplicates, longest chain, renders per interaction) with `docs/perf/frontend-baseline-2026.md`; runner timings are not comparable across machines. Timing-based numbers (LCP, Lighthouse) are deliberately not gates.
